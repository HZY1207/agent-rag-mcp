# 01 · 项目初始化与最小骨架

> 本步产出：可运行的 FastAPI 骨架 + 配置中心 + 统一响应体
> 完成标志：`/api/health` 返回 `{"code":0,...}`，`/docs` 能打开接口文档

---

## 1. 我们要造什么：三件套关系图

- **RAG** 解决"模型不知道你的私有知识"：先检索、再让模型基于检索结果回答，并标注引用。
- **Agent** 解决"一次问答不够，需要多步行动"：模型自己决定"先检索知识库 → 发现缺信息 → 再调一个工具 → 最后回答"。
- **MCP** 解决"工具和数据源的接入不标准"：把工具按统一协议暴露，任何支持 MCP 的应用都能即插即用。

```
用户提问
   │
┌──▼─────────────── Agent 引擎（LangGraph 编排的循环）──────────────┐
│  模型思考：下一步做什么？                                          │
│    ├─ 需要私有知识 → RAG 链路 → Qdrant 向量检索 → 带引用的片段      │
│    ├─ 需要调工具   → MCP 客户端 → 外部 MCP Server（文件/网页/…）    │
│    └─ 信息够了     → 生成回答                                     │
└──┬───────────────────────────────────────────────────────────────┘
   │ SSE 流式
聊天界面（展示思考过程、工具调用轨迹、引用来源）
```

**记住三个角色的比喻**：RAG 是"图书馆"（翻开正确的书页），Agent 是"研究助理"（决定要查什么、查几轮），MCP 是"标准插座"（任何工具插上就能用）。

## 2. 技术选型一句话理由

| 选型 | 为什么 |
|---|---|
| FastAPI | 路由 + 数据校验 + 自动 API 文档三合一；原生 async，适合 SSE 流式和并发调用模型 |
| uvicorn | ASGI 服务器：真正"跑"FastAPI 的引擎（FastAPI 管怎么处理请求，uvicorn 管怎么接收请求） |
| LangGraph | LangChain 生态的 Agent 编排框架，用"状态图"描述 Agent 的循环，比手写循环易维护、可扩展 |
| MCP 官方 SDK | 客户端/服务端双向都支持，Python 版最成熟 |
| Qdrant（本地模式） | 零依赖起步：pip 装完直接用文件存向量，之后要部署了再切 Docker 服务模式 |
| SQLite | 单文件数据库，会话/消息存它，开发期零运维 |

## 4. 代码讲解

### 4.1 三个依赖的分工

- `fastapi`：Web 框架，负责"请求进来后怎么处理"（路由、参数校验、序列化、文档生成）。
- `uvicorn[standard]`：ASGI 服务器，负责"监听端口、收发 HTTP、调用 FastAPI"。
- `pydantic-settings`：把 `.env` / 环境变量变成**类型安全**的 Python 对象。写错类型会立刻报错，而不是运行时才发现。

### 4.2 虚拟环境 venv

每个项目一个 `.venv`，原因：不同项目依赖不同版本（A 项目要 langchain 0.2，B 项目要 0.3），装到全局 Python 里必然打架。`.venv` 就是"只属于这个项目的依赖箱"。

> 小技巧：不激活也能运行——直接把解释器写全路径：`.venv\Scripts\python.exe -m uvicorn ...`。激活只是为了少打几个字。

### 4.3 config.py：配置中心

- `Settings(BaseSettings)`：字段即配置。声明 `llm_api_key: str`，就会自动去读环境变量 `LLM_API_KEY` / `.env` 里的同名项。
- 优先级：**环境变量 > .env > 代码默认值**。部署时用环境变量覆盖，本地开发用 .env，都方便。
- `@lru_cache`：把 `get_settings()` 变成单例。配置只解析一次，全进程共用（避免每次请求读一遍文件）。
- 好处：以后加配置 = 加一行字段 + 一行 `.env.example` 说明，全项目步步透明。

### 4.4 common.py：统一响应体

所有普通接口返回 `{code, message, data}`：
- `code=0` 成功；非 0 为业务错误码（后续统一枚举）。
- 前端只需写一套"解包"逻辑。
- 例外：SSE 流式接口不是一次性 JSON，而是持续推送事件（第 2 步细讲）。

### 4.5 main.py：应用入口的四个关键点

1. **`FastAPI(...)` 实例**：整个应用的"根"。
2. **`lifespan`**（生命周期钩子）：启动时初始化资源、关闭时释放资源。后续步骤会在这里连向量库、建 SQLite 表、启动 MCP 客户端。写成 `async with` 风格的上下文管理器，是 FastAPI 推荐的姿势。
3. **CORS 中间件**：浏览器的同源策略会拦截"网页域名 ≠ 接口域名"的请求。前端开发服务器在 `:5173`，接口在 `:8000`，所以必须显式允许。注意：拦截发生在**浏览器**，用 curl 测试不受影响。
4. **`include_router(api_router, prefix="/api")`**：路由模块化——各业务模块自己定义路由，由 router.py 聚合，main.py 只挂一个总入口。

### 4.6 router.py：路由聚合

```python
api_router.include_router(health.router)
# 后续：api_router.include_router(chat.router)、documents.router、sessions.router ...
```

## 6. 常见问题

- **激活 venv 报"禁止运行脚本"**：执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（只放开本地脚本，安全）。
- **pip 装得慢**：配置国内镜像 `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`；或临时 `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。
- **8000 端口被占用**：换端口 `--port 8001`；或找出占用进程停止。
- **`.env` 不生效**：确认文件在项目根目录（和 `.venv` 同级）、字段名拼写正确（`LLM_API_KEY`）。
- **pip 报 `UnicodeDecodeError: 'gbk' codec can't decode...`**：`requirements.txt` 里写了中文注释。pip 在中文 Windows 上按 GBK 解析该文件导致失败（本步已实际踩坑），改成纯英文注释即可。
- **终端里中文显示乱码**：PowerShell 5.1 的 `Invoke-RestMethod` 解析 UTF-8 响应有已知缺陷，属于"显示问题"不是"数据问题"，用浏览器或 Python 请求验证即可。
- **`/docs` 白屏**：FastAPI 默认从 `cdn.jsdelivr.net` 加载 Swagger UI 的 JS/CSS，外网 CDN 不稳定就会白屏（本项目已修复：静态资源本地化到 `app/static/`，并在 main.py 自定义 /docs 路由；资源取自 npmmirror 的 swagger-ui-dist@5.33.3）。自查此类问题的通用方法：F12 → Network 面板，看哪条请求是红色的，点开看失败原因（超时 / 被拦截 / 404）。
